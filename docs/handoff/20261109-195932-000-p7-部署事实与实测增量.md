## 2. `__name` 垫片：根因、修复、守卫边界

**根因**：wrangler/esbuild 的 `keep_names` 会把 `Function.prototype.toString()` 拿到的函数体里插入 `__name(fn, "fn")` 调用；`src/ui/templates.js` 把一批函数 `toString()` 后拼进内联 `<script>` 下发，浏览器没有 `__name` 这个 helper → 第一条语句就 `ReferenceError`，整段脚本中止，后台按钮全废。语法检查全绿也拦不住，因为它只解析不执行。

**修复**（`src/ui/templates.js`，当前行号）：

- `:592-594`：定义垫片 `const __name = (fn, name) => { try { Object.defineProperty(fn, "name", { value: name, configurable: true }); } catch (e) {} return fn; };`
- `:566` 附近：把垫片定义拼在内联脚本最前面再注入其余函数体。

**守卫**：`scripts/check-dashboard-script.mjs`（`pnpm check:dashboard`）：

- 能做到：① 真正渲染一次页面，取出每段内联脚本，用 `new Function(code)` **只解析不执行**做语法闸门；② 不变量检查——脚本里每个 `__xxx(` 调用都必须在同一段脚本内先有 `const/let/var/function __xxx` 声明，否则 exit 1。
- 做不到：**运行时 `ReferenceError` 抓不到**（workerd 禁 `eval` / `new Function`，这段脚本无法在 vitest 里求值；守卫本身也只解析）。另外它**没有接入 `pnpm check`**（避免 CI 出现 Node 与 workerd 行为不一致的门禁），改完模板要手动跑一次。

复现路径（若怀疑垫片再次失效）：本地起 `pnpm dev --port 8789`，浏览器打开 `/admin` 并登录，F12 Console 看是否有 `__name is not defined`，并点几个按钮确认交互未失效。
