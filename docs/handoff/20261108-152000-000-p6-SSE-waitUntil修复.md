## 1. 高-1 为什么成立（Cloudflare 语义）

响应体结束即请求生命周期可结束；未注册的 Promise 不被运行时延寿。
原注释「关流后任务仍会跑完」是错的——关流只是停止推送，任务能否跑完取决于调用方是否注册 `waitUntil`。
仓库里早有同类约定可对照：`src/routes/github-proxy.ts:36` `(promise) => ctx.waitUntil(promise)`、
`src/sync/github.ts` 的 `waitUntil?: WaitUntil` 与 `:286 if (waitUntil) waitUntil(write)`。

## 3. 两个坑（都踩过，可复用）

- **`index.ts` 别用箭头包一层**：`(p) => ctx.waitUntil(p)` 会在 `/api/` 分支里新增一个函数，
  而该分支没有单测覆盖 → functions 覆盖率白降 1.04pp（实测 87.70 → 86.66）。用 `ctx.waitUntil.bind(ctx)` 无此问题。
- **断言注册的 Promise 之前必须先排空流**：`TransformStream` 的 `writer.close()` 要等可读侧被排空，
  先 `await registered[0]` 会死锁超时。正确顺序：`const drained = drain(res)` → `await registered[0]` → `await drained`。
  真实客户端一直在读，所以生产不触发，只有测试里会咬。
