## 4. 关键决策与理由（这些是硬的，别推翻）

1. **删掉 UUID 格式强校验**（中途我曾加 `UUID_RE` 硬失败，用户明确否决）。
   用户原话（m00104）：`当前修改方案存在问题：1 database_id 取值格式不一定是uuid格式，还有可能是其他字符串，不应该限定死其格式`
   支撑事实：wrangler `config-schema.json` 把 `database_id` 声明为裸 `string`（`"The UUID of this D1 database (not required)."`，无 pattern）；wrangler CLI 里 grep `must be a UUID` / `not a valid UUID` / `invalid database_id` 零命中；wrangler v4 支持缺省 `database_id` 的自动供给并回写 ID。→ 格式与存在性是 wrangler / Cloudflare 部署期的职责，本地再猜格式只会误伤合法值。
2. **只判哨兵值与空值**（不变量最小化）。哨兵值判定 = `trim()` + 大小写不敏感全等，是**单点可枚举**判定，不是模式匹配（明确否决了「`REPLACE_WITH_*` / `YOUR_*` / `xxx` 模式清单」这种猜测式扩展）。
3. **输出契约**：失败/成功都不回显字段值（避免 ID 进 CI 日志；哨兵值本身在报错文案里无信息量），只报 `binding` 名；「未替换」与「缺失或为空」分两条 → 操作者能区分「忘了替换」和「整个字段没写」。
4. **保持零依赖行扫描**，不引入 TOML 解析器（AGENTS.md 禁止新依赖）。承诺的子集写在 `scripts/predeploy.cjs:24`：非注释行上的 `key = "值" / '值' / 裸值`，行尾 `#` 注释被排除；不处理多行字符串与转义。
5. **不写 ADR**（这条决定几行代码就能回退），溯源用 `FIX-20` 注释；术语落 `GLOSSARY.md`。
