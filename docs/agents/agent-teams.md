# 多 agent 协作公约（AgentTeams）

本文件是 agent 团队跑票时的行为约定。触发条件：用 `/agent-teams` 建队、或接手已有团队的票。

## 泳道

四类票，四类成员，**互不越界**：

| 泳道 | 成员职责                       | 票面前缀 |
| ---- | ------------------------------ | -------- |
| 实现 | 写代码、跑红绿、开 PR          | `实现`   |
| 评审 | 只读、独立复跑验证、给 verdict | `评审`   |
| 文档 | README / docs / 交接           | `文档`   |
| 合并 | 只做合并与台账回执             | `合并`   |

调度器会把票派给**当前空闲**的成员，不看泳道。所以：

- 建票时把泳道写进 subject 前缀（如「评审 #37：…」）。
- 成员开工前先核对自己的泳道：前缀不匹配就**不 claim**，回 captain 说「泳道不符」。
- 合并票永远不派给只读评审成员。

## 改派纪律

`reassign_task` 会撤销对方正在跑的 attempt。**改派前先确认那张票有没有在跑**：

- 票还没人 claim → 可以直接改派。
- 票已被 claim / in_progress → 先 `send_message` 下停手令，确认对方停下再改派。
- 成员被一张票占用时会挡住新票（同时只能持有未完成任务）→ 需要它做别的，先把旧票收回或取消，别让它干等。

## 合并纪律

- 合并只走 `node scripts/merge-pr.mjs <pr> <放行 hash>`（或 `pnpm merge:pr`）。脚本会现查 state / mergeable / mergeStateStatus / head，**head 与放行 hash 不一致直接拒绝**。
- 放行必须由 captain 给出目标 head；放行消息与合并回执都要留 hash，回执是台账。
- 收到「已改派」「停手」后，**不得再用旧 attempt 执行不可逆动作**（merge / push / force-push / delete）。2026-11-09 有一次只读评审成员用已撤销的 attempt 合并了 PR，合入的恰好是评审通过版才没出事。
- 合并回执至少含：merge commit、mergedAt、PR state、关联 issue state、远端分支是否已删、各 worktree HEAD。

## 验收口径

- 实现方自述只能算「候选结果」，verdict 由评审独立复跑决定。
- 红必须真红：`main` 已修好的缺陷上新增用例会天然绿，此时用**回退实现**取红；回退点选错（碰不到被守护路径）会得到假绿，评审要复跑一遍变异确认。
- captain 给的判定标准也可能错——成员实测发现口径无效时，先摆证据再执行，captain 负责更正票面与契约。
